Écho redémarre même quand sa base de données est restée verrouillée après un arrêt brutal.

## Nouveautés dans 0.4.0.4

### Corrections
- **« The built-in server did not start » après une mise à jour du système.** Le rapport de la 0.4.0.3 a montré la cause : « database is locked ». Écho protège sa base de données avec un petit dossier de verrouillage, retiré quand l’écriture est finie. Si le téléphone arrête Écho en pleine écriture (mise à jour Android ou One UI, arrêt forcé, batterie), ce dossier reste, et chaque démarrage suivant échoue en croyant que la base est utilisée. Écho se bloquait donc à l’écran de démarrage, même après un redémarrage du téléphone.
  - Maintenant Écho retire ce verrou au lancement. Il est le seul à utiliser sa base (un seul moteur par appli), donc un verrou trouvé au démarrage est forcément un reste.
  - Ta bibliothèque, tes playlists et tes réglages ne sont pas touchés : seul le verrou est retiré.
- Un test vérifie ce cas : une base avec un verrou laissé par un arrêt brutal s’ouvre normalement.

### À savoir
- Les versions 0.4.0.3 et suivantes affichent un rapport quand Écho ne démarre pas, avec un bouton « Copier le rapport ».
